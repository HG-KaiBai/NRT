# Simulation testing

See [the workflow guide](../README.md) for the complete case matrix, configuration, and reporting commands.

Each replication has 35 cases: five exact cases and 30 censored cases. Each NRT loss uses all 35; NNCDE and DeepSurv each use 15. The CPU methods together have 140 applicable method/case combinations per replication. Exact data is fitted once per setting.

Submit `run_nrt.sh`, `run_nncde.sh`, `run_deepsurv.sh`, and `run_cpu.sh` after tuning. The NRT script runs three GPU tasks, one per loss, with 500 sequential replications per GPU. NNCDE and DeepSurv each use one GPU sequentially. The CPU script runs a 500-task array. Each task first runs the 110 applicable combinations of deep distribution regression, Ctree, Cox, and AFT across its CPU cores, then closes the worker pool and runs the 30 ICcforest cases sequentially. Parallel fits use fresh worker processes to release retained memory between cases. `PARALLEL_FITS` controls the first phase; `ICCFOREST_PARALLEL_FITS` defaults to 1 for the separate forest phase.

`simulation.py` reads parameters and `tau` from `testing/hyper_para/<method>.csv` for DeepSurv, NNCDE, and all three NRT losses. Each row matches a case through `data_types`; `parameters` contains a JSON object. CPU methods read `tau`, `mu`, and `r` from `tuning/output/cases/<case_id>.json`. They do not read hyperparameter CSVs. Override the tuning output directory with `--tuning-dir` or the launchers' `TUNING_DIR`. For neural methods, override the CSV directory with `--hyper-dir` or `HYPER_DIR`; generator settings default to `mu=0`, `r=None`, so pass `--mu` and `--r` if the CSVs were tuned with other values.

Each fit writes one resumable JSON result per method/case/replication and records realized right-censoring rates. When an invocation finishes, it checks the shared JSON files and automatically writes `testing/output/tables/<case_id>.csv` for each complete data setting (distribution, observation scheme, and q). The general testing launchers default to `SUMMARY_METHODS=all`, so each table waits for every applicable CPU and GPU method to finish all replications. For a subset run, set the same `SUMMARY_METHODS=NRT_NLL,NNCDE` (or another comma-separated list) in every participating launcher, or pass `--summary-methods ...`. Direct Python runs default to their `--methods` selection.

Each method selection also produces one combined censoring report, `censoring_<methods>_rep1_<replications>.csv`, once all its requested cases and replications succeed. The CPU array therefore writes one 140-row report across all 500 replications, independently of GPU completion, instead of one CSV per array task. Each row contains the replication count, mean right-censoring rate, sample standard deviation, and mean difference from q. Pending or failed replications preserve an existing report. To rebuild only this report from saved JSON results, run `python -m testing.simulation summarize --methods deep_distribution_regression,ctree,iccforest,cox,aft --censoring-only` from the NRT root, with matching case and replication options if they differ from the defaults.

Each table contains a `replication` index and one column per applicable method, using `average_grid_sse`. The default is 500 replication rows followed by `average` and `standard_deviation` rows, for 502 rows total. Standard deviation uses the sample formula. Automatic summaries require all requested results to succeed and preserve existing tables for pending cases. Once all selected cases complete, `censoring_summary.csv` counts each dataset once across methods. Writes are atomic, including concurrent finishers and resumed workers. To rebuild existing tables manually, run `python -m testing.simulation summarize` from the NRT root with matching case, method, and replication options. Manual `--allow-incomplete` summaries preserve replication numbers and leave missing/failed values blank. `main.py` accepts the same CLI.

NRT and NNCDE fits use 200 epochs by default; NRT uses learning rate 0.001. DeepSurv uses 1,000 epochs and `PAPER_GAUSSIAN_PARAMETERS` defaults for settings absent from its CSV. Saved CSV parameters are retained. Override epochs with `--epochs ...`. For tuning grid changes, see [the tuning guide](../tuning/README.md).

The single-fit notebooks and model implementations remain available. Choose `joint_nll`, `joint_brier`, or `alternating` for NRT. `testdata2.md` describes the distributions and observation process.

Startup checks and requeue are described in [the workflow guide](../README.md#node-checks-and-requeue). All launchers enable requeue and append logs; node checks run before fits or CPU workers begin.
